Commands

Five commands, one job each.

zap install <archive|github-url>
zap list [--origin]
zap update [<id>...] | --all
zap remove <id>
zap bundle <dir>

Common flags

Every command that reads or writes app roots takes these.

FlagEffect
--apps-dir <dir> Directory holding app roots, one per app. Defaults to $APP_HOME, then ~/.apps, or /opt/apps with --system.
--system Use the system scope: /opt/apps and /usr/local/bin. Needs write access there, so usually sudo.

install

Takes three kinds of input.

  • A bundle archive: .tar.gz, .tgz or .zip whose root holds exactly one <id>/ directory.
  • A GitHub release URL, e.g. .../releases/tag/v0.12.2. The asset matching this platform is downloaded and wrapped.
  • A GitHub repository URL, e.g. github.com/owner/repo. The head of the default branch is installed, versioned by its short commit hash.
FlagEffect
--force Replace an existing install, including its data/. For an upgrade that keeps data, use update.
--id <id> Bundle id to use for a GitHub install. Beats the id declared in the tree's own app.toml.
--name <name> Display name to use for a GitHub install.

Identity for a GitHub install comes from, in order: --id and --name; then whatever the tree's own app.toml declares; then io.github.<owner>.<repo>. An authored id wins over the derived one because it is the stable one: a repository that changes hands does not move an installed app.

list

Reads the scopes' manifests and prints what is installed. A directory holding no app.toml is not listed; what a plain removal leaves behind is data/ alone.

FlagEffect
--origin Add a column showing where each app came from, read from its receipt.toml.
ID                         VERSION  KIND      NAME       ORIGIN
io.github.huyng.bashmarks  f051b9d  payload   bashmarks  https://github.com/huyng/bashmarks@f051b9d
io.github.neovim.neovim    v0.12.6  payload   neovim     https://github.com/neovim/neovim/releases/tag/v0.12.6

update

Re-fetches whatever the install's receipt.toml names: the latest release for a release source, the branch head for a repo source, the same file for an archive source.

The new tree replaces app.toml, contents/ and receipt.toml. data/, cache/ and run/ are moved across, so settings survive. An upgrade is refused if the fetched bundle's id differs from the installed one.

FlagEffect
--allUpdate every app in the scope.
--check Report what would change, install nothing.

Version strings carry no ordering, so update reports a source that offers something different, not something newer. A project that republishes an older version is installed like any other change; --check shows it before you commit to it.

An app installed without a receipt cannot be updated, and neither can one whose archive has been deleted. Reinstall it to record where it came from.

remove

Deletes app.toml, receipt.toml, contents/, cache/ and run/, and takes away the exposed command. data/ is kept, so a later install of the same id finds its settings again.

FlagEffect
--purge Delete data/ too. This loses user data.
--force Remove the directory even when it holds no readable app.toml.

An exposed command is only removed when it really points into the root being deleted. A symlink or wrapper that belongs to something else is left alone.

bundle

Packs an app tree into a .tar.gz that installs with zap install. The input is either a bundle root (app.toml beside contents/) or a flat source tree (app.toml beside the files). See Bundles.

FlagEffect
--out <dir>Where to write the archive. Defaults to the current directory.
--os <token> Platform token in the archive name. Defaults to this machine's; pass "" to leave it out.
--arch <token> Architecture token. Same default and empty-string rule.

Exit status

0 when everything asked for was done. 1 when anything failed, including one app out of a --all run: the other apps are still attempted, and each failure is reported on its own line.

Environment

VariableUsed for
APP_HOME Directory holding app roots, same meaning as in the specification. Overridden by --apps-dir; ignored with --system.
HOME Locating ~/.apps and ~/.local/bin.

zap sets APP_ROOT for apps it exposes at system scope, through the wrapper script it writes. It never sets it for a user install, where a symlink into the root is enough.
