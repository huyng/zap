zap

A package manager for self-contained apps. An app is one directory: installing puts it in place and links one command, removing deletes it.

curl -fsSL https://raw.githubusercontent.com/huyng/zap/main/install.sh | sh

That downloads the release for your platform, checks its checksum, and unpacks it to ~/.apps/io.github.huyng.zap/, exposing zap in ~/.local/bin.

Use

zap install https://github.com/neovim/neovim/releases/tag/v0.12.2
zap install https://github.com/huyng/bashmarks     # a repo with no releases
zap install ./my-tool.tar.gz                       # a bundle archive

zap list [--origin]                                # what is installed
zap update <id> | --all [--check]                  # fetch its source again
zap remove <id> [--purge]                          # uninstall, keeping data/
zap bundle <dir> [--out dist]                      # pack a tree for release
ScopeApp rootsExposed command
user (default) $APP_HOME or ~/.apps ~/.local/bin
system (--system) /opt/apps /usr/local/bin

Both flags on every command that touches app roots: --apps-dir <dir> moves the parent directory, --system selects the system scope.

A bundle

An archive holding exactly one <id>/ directory, with an app.toml beside a contents/ tree:

org.example.tool/
├── app.toml
└── contents/bin/tool
id = "org.example.tool"      # lowercase, dot-separated, names the app root
name = "tool"
version = "1.0.0"            # display metadata only, no ordering
entrypoint = "bin/tool"      # optional: omit for a payload that runs nothing

The tree is self-contained: libraries and runtime inside contents/, nothing fetched when it starts. That is what makes deleting the directory a complete uninstall.

What an install looks like

~/.apps/org.example.tool/
├── app.toml          # from the bundle
├── contents/         # from the bundle, replaced wholesale on upgrade
├── receipt.toml      # written by zap: where it came from
├── data/             # durable state, kept across upgrades and removals
├── cache/            # regenerable
└── run/              # session-scoped

receipt.toml records the source, the artifact's SHA-256 and which zap installed it. It is what update reads to decide what to fetch again, is never shipped inside a bundle, and is deleted with the installation.

What it leaves out

No dependency resolution, signing, services, or build step. Each is a different problem; a manager that only moves directories stays small enough to audit. Compiling stays the project's job — a project assembles its tree, then zap bundle packs it.

Conformance

An install is a conforming app root of the App Bundle Layout Specification, so the layout on disk is the specification rather than a convention of zap's own. Upgrades assemble the new tree in a staging directory and rename it into place, so contents/ is always either the old tree or the new one and never a mixture.

Manifest, bundle and uninstall rules are the specification's. What zap adds is receipt.toml, which the specification defines as install state: written by the installer, opaque to the app, removed with the installation.
