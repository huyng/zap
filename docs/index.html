A package manager for self-contained apps

An app is one directory. Installing puts it in place and links one command. Removing deletes it.

Install

curl -fsSL https://raw.githubusercontent.com/huyng/zap/main/install.sh | sh

That downloads the release for your platform, checks the published checksum, and unpacks it to ~/.apps/io.github.huyng.zap/. Then:

zap install https://github.com/neovim/neovim/releases/tag/v0.12.2
zap list
zap remove io.github.neovim.neovim

Nothing is compiled, configured or signed at install time. zap unpacks a tree, checks it, puts it in place and makes one symlink.

What it does

install

Unpack a bundle, verify it, place it in a scope, link its entrypoint.

update

Re-fetch whatever the install came from, swap the tree, keep the data.

remove

Delete the tree and its record, keep data/ unless purged.

bundle

Pack an app tree into an archive you can publish as a release asset.

What it deliberately leaves out

No dependency resolution, no signing, no services, no build step. Each of those is a different problem, and a manager that only moves directories stays small enough to audit.

An app is expected to arrive self-contained: libraries and runtime included in its tree, nothing fetched when it starts. That is the whole contract, and it is why removing a directory is a complete uninstall.

Where things go

Scope App roots Exposed command
user $APP_HOME or ~/.apps ~/.local/bin
system /opt/apps /usr/local/bin

The layout inside a root never changes between the two. See Conformance for how that maps onto the specification.
